**真因链**：Unity 把 `jar:file://!/assets/Videos/mobge_and_senri_splash_video.mp4` 交给
`libunity+0x4c124c`（asset 路径翻译，一个虚调用转发 thunk）→ 翻译失败 → `-10004` → 没有片头视频 → 黑屏。

**定稿契约**（消费者函数 `0x53f020`，`bl 4c124c` 在 `0x53f150`；本地副本 build-id `664018de…` 一致）：

| 参数 | 语义 |
|---|---|
| a1 | `string*` **输入/输出**：进来装原始 URL；调用**前**被 `106178(a1, NULL, 0)` 清空；**必须回填本地路径** |
| a2 | `void**` 数据基址；**NULL = 数据在文件里**；非 0 会被加进 offset → 变成传给 extractor 的文件偏移 |
| a3 | `size_t*` 数据总长；同时是 `offset + size <= *a3` 边界检查的上界 |
| 返回 | `bool`（bit0） |

下游：`53f308 open(*a1)` → `[vtbl+136](obj,fd,offset,len)` == `setDataSourceFd`；
或 `53f2c4 [vtbl+144](obj,path)` == `setDataSourcePath`。
外层 `x20 = size`、`x22 = offset`，字面证据是错误串 `"…OpenExtractor offset(%d)+size(%d)"`（`0xbde8d5`）。

**四次迭代（每一步都被日志钉死）**：

| 版本 | 写法 | 结果 |
|---|---|---|
| v1 | 只 `return (uintptr_t)path.c_str()` | bit0==0 → `tbz w0,#0` 恒失败 → `could not translate` → `-10004` |
| v2 | 写 a2=路径指针 / a3=路径长度 + `return 1` | tbz 过了，但 a1 没回填 → `open("")` → `unable to open , error: 0` → `-10004` |
| v3 | 回填 a1 + a2=内存缓冲 / a3=文件长 | 路径与 open 全对（`fd=30`），但 a2 被当 offset 基址 → `offset=70369750858784` → `Invalid data found` → `-10000` |
| **v4** ✅ | 回填 a1 + **a2=NULL** + a3=文件长 + `return 1` | `offset=0`、`tracks=2`、`decoded frame=0/1`、**画面出来** |

### ✅ L2 定论：hostless URL 的 host 来源已定位（2026-09-22 深夜）

**结论一句话**：host = `Application.dataPath`，它由 `Context.getPackageCodePath()`
（port 侧 `bd_compute_source_dir()`）供给，但被 **Unity 的 `stat()` + `S_IFREG` 闸门**挡下 ——
返回的 `<cwd>/UnityDataAssetPack.apk` **在磁盘上不存在** ⇒ 候选作废 ⇒ `dataPath=""`
⇒ `streamingAssetsPath = "jar:file://" + "" + "!/assets"` ⇒ **host 为空**。

**完整链（静态 + 运行时双向吻合）**

| 环节 | 地址 | 内容 |
|---|---|---|
| URL 构造函数 | `libunity+0x47e940`（唯一调用点 `0x2fd1dc`） | `"jar:file://" + F() + "!/assets"`，**对 F() 无校验** |
| F() | `0x39f800` → `0x4bbe14`（取单例 `*(libunity+0xF0B88)`）→ `0x4bfbe8` | 尾调用 `obj=*(singleton+8)` 的 `vtbl[0x170]` |
| **槽 0x170 真身** | `libunity+0x30c704` | `return std::string(g_appPathBuf)`；`g_appPathBuf` @ `libunity+0xF0B740`（`.bss`），经 GOT 槽 `0xE8BC08`（`R_AARCH64_RELATIVE` addend=`0xf0b740`）取到 |
| **唯一写入者** | `0x39f818`（SetDataPath）← 唯一调用者 `0x31c520` | 包在 `SetDataPathChecked(p)`（`0x31c4cc`）里 |
| **闸门** | `0x31c56c` CheckPath | ① `stat(p)` 必须成功；② `(st_mode & 0xF000) == 0x8000`（**普通文件**）；> 通过才打 `[VFS] Mount %s` |

**运行时铁证**
- `log:660 [BD-DATADIR] getPackageCodePath -> …/UnityDataAssetPack.apk` → `log:661 [NATIVE] stat(同一路径)`：Unity 拿到就 stat。
- 探针：`Application.dataPath = ''`、`streamingAssetsPath = 'jar:file://!/assets'`（Unity 自己就报 hostless）。
- 全仓 `grep -c "\[VFS\] Mount"` = **0**：没有任何候选通过过 stat。
- 运行时 vtbl 与静态推断**逐位一致**：`vtbl=0x3800e5c068`、`vtbl[0x170]=libunity+0x30c704`。

`dataPath` 立刻变成 `/game/Oddmar/gamedata/UnityDataAssetPack.apk`（**正是 getPackageCodePath 的返回值**）、
