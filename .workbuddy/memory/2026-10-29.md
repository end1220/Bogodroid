## 新端口：Blackmoor 2（黑暗荒野2）容器测试

从已连接的 Redmi K30 Pro（adb `96527589`）拉取 `com.fourfats.blackmoor2`，
用户称"暗黑荒野2"，百科名"黑暗荒野2"，label 只有英文 `Blackmoor 2`（APK 无 zh label）。

### 目标特征（决定了移植难度）

- **Unity 6000.0.70f1**（从 globalgamemanagers 内 `6000.0.70f1` 确认），IL2CPP，arm64-v8a
- App Bundle 分包，共 7 个 APK、约 584MB：
  - `base.apk` 50MB、`split_config.arm64_v8a.apk` 39MB
  - `split_UnityDataAssetPack.config.astc.apk` **469MB**（8005 个 hash 命名 bundle）
  - `split_UnityTextureCompressionsAssetPack.config.astc.apk` 25MB
- **关键坑：`globalgamemanagers`（20MB）+ `level0` 在名字带 "TextureCompressions" 的那个
  25MB split 里，不在 DataAssetPack 里。** 只解大的那个包会一直 "Unable to initialize the
  Unity Engine"。解包必须把所有 split 的 assets 合并。
- 原生库有加固：`libpglarmor.so` / `libnms.so` / `libbuffer_pgl.so`；libil2cpp 76MB，
  `addr2line` 出来全是 `DllCanUnloadNow` / `CloseNLSocket` / `JNI_OnUnload` 之类假符号。
- 带 Firebase / Crashlytics / 穿山甲(`libtt_ugen_layout.so`)，有内购。

### 本轮修掉的 3 个 loader 缺陷（都在通用层，非游戏专属）

1. `projects/unityloader/main.cpp` — **`initJni` 签名兼容**：Unity 6000.0.x 注册的是
   `(Landroid/content/Context;I)V`（没有 cmdline String），原代码只认 `(Context,int,String)V`
   和 `(Context)V`，直接 fatal "did not register it"。已加中间分支。
2. 同文件 — **`initJni` 查找位置**：Unity 6000.0.x 是**混合布局**，
   `initJni` 仍在 `com/unity3d/player/UnityPlayer`，而 `nativeRender` 等已搬到
   `UnityPlayerForActivityOrService`。原代码把查找绑在承载 nativeRender 的类上，必然 miss。
   改为 `find_init_jni` 先查 render 类、再回退基类。
3. `javastubs/javac.cpp` — **`Class.forName(String,boolean,ClassLoader)` 三参数版本**未 hook。
   Unity 6 用它加载 `PlayAssetDeliveryUnityWrapper`，拿 null 后所有 PAD 调用变成
   `Class is null` → wrapper 不存在 → libunity 空指针调用（`pc=0` at libunity+0x7c7f08）。
   已补 3 参数 hook（与 1 参数共存，HookManager 按 lambda 推导签名注册，不互相覆盖）。
4. `projects/unityloader/javastubs/unity.cpp` — `getAssetPackPath("UnityDataAssetPack")`
   优先返回真实解包目录 `<root>/assets`，退而才用 `.apk/assets`。

### 现状

- 引擎启动成功：场景加载、**C# 托管代码在跑**（`FFAds Ads.Awake` 是游戏自己打的），

## Blackmoor 2 续：主菜单已渲染（本轮重大进展）

上一段记的 UMP 卡点已解决，**游戏现在能跑到主菜单并进剧情过场，60–90s 不崩**。

### 本轮新增/修改（3 处）

1. **新增 `projects/unityloader/javastubs/ump.h` + `ump.cpp`**（GLOB 自动收进构建，
   不用改 CMakeLists）。整套 Google UMP 同意 stub：`UserMessagingPlatform`、
   `ConsentInformation`、`ConsentRequestParameters(+$Builder)`、
   `ConsentDebugSettings(+$Builder)`、`ConsentForm`、`FormError`，在 `binding.cpp` 注册。
   关键点：**Unity 的 AndroidJavaObject 桥会把对象返回值和 AndroidJavaObject 参数
   擦成 `Ljava/lang/Object;`**，例如 `getConsentInformation` 实际签名是
   `(Lcom/unity3d/player/UnityPlayerActivity;)Ljava/lang/Object;`，
   `setDebugGeography` 是 `(I)Ljava/lang/Object;`。按 Java 文档签名注册会一直
   STUB-MISS。策略：按擦除签名声明 C++ 方法（返回 `std::shared_ptr<jnivm::Object>`），
   同时保留一份按真实 Java 类型的重载；C++ 靠不同成员名区分（如
   `getDeviceIdsErased`），descriptor 里挂同一个 Java 名。
   `requestConsentInfoUpdate` / `loadAndShowConsentFormIfRequired` **故意不回调监听器**
   （那是托管 proxy，走 proxy dispatch 太深，且离线本来无可报告）。
2. **`thunks/libc/misc.cpp` + `impl_tab.h` + `impl_header.h`：`inet_ntop` 守卫。**
   第 11 轮崩在 libc `inet_ntop4`（`pc libc+0xed640`，`ldrb w5,[x0,#3]`，`x0=4`，
   `si_addr=0x7`），线程 `IL2CPP Threadpo`。`(void*)4` = `NULL + offsetof(sockaddr_in,sin_addr)`
   ——网络调用失败后没判空就格式化地址。已把 `THUNK_DIRECT(inet_ntop)` 换成
   `NO_THUNK("inet_ntop", &inet_ntop_safe_impl)`，src 低于 0x1000 时返回 `0.0.0.0`/`::`
   并用 `bd_describe_address` 记一次调用方。**注意：之后几轮 `BD-NETGUARD` 一次都没打，
   崩也确实没再出现，所以修复归属还不能确认，别当成已证实的因果。**
3. **`javastubs/android.h` + `android_view.cpp`：`InputDevice` 擦除签名重载。**
   Unity 6 用 `(I)Ljava/lang/Object;` / `()Ljava/lang/Object;` 且 **static=0** 去取
   `getDevice` / `getDeviceIds`，原来只注册了 `static` + `()[I` / `(I)Landroid/view/InputDevice;`，
   必然 miss。加 `getDeviceErased` / `getDeviceIdsErased` 后 STUB-MISS 消失。
4. `platform/common/input_backend.cpp`：`getDevice` / `getDeviceIds` 加了 `BD-INPUT-ENUM`
   日志（诊断用，确认 Unity 真的枚举了设备）。
